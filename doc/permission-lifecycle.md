# 保存即生效的权限设计

应用是权限隔离边界。角色授权、角色启停、用户角色绑定、菜单和 API 保存成功后直接生效；删除也直接生效。没有草稿/发布状态、发布按钮、角色版本、应用版本、历史策略和持久化权限快照。

## 运行时行为

`POST /api/v1/authorize` 的请求需要 `appKey`、`serviceResource`、`subject`、`method`、`path`；`domain` 可选，省略或传空白按默认空域处理，旧值 `global` 也归一到同一默认空域。应用/服务/用户（含域）定位权限范围，method/path 确定具体接口。身份必须来自可信登录态，客户端不传角色。多个启用角色的权限取并集。

默认域是数据库非 NULL 空串 `''`：省略 `domain` 就是使用默认域。旧字符串 `global` 是默认域的兼容别名，与空串指向同一组绑定；其它非空具名域仍按域隔离，不会被合并，也不会因为省略 `domain` 而获得具名域权限。

权限模拟与真实鉴权均读取当前已保存配置；用户菜单也按当前角色与菜单绑定计算。鉴权结果包含 `allowed`、`effect`、`reason`、`matched_roles`，不再返回 `release_version`。Go SDK 已适配该响应；旧 SDK 对发布版本的校验会拒绝新响应，需要同步升级。

保存事务提交后开始读取权限的新请求使用已提交的数据。提交前已开始读取的在途请求可以完成其已读到的判断。数据库不可用或服务目录读取失败时返回错误，SDK 拒绝访问，不使用无法验证的新旧缓存放行。

## 缓存一致性

直接对数据库保存后再尝试删除 Redis，有“删除失败”和“旧加载迟到回填”的竞态。当前实现用数据库事务内更新的 `applications.policy_token` 校验缓存，它是随机 UUID 的**内部失效标记**，不提供版本序列、历史、回滚或发布操作，也不进入 Redis key。

数据库 statement 级触发器覆盖角色、角色 API/菜单授权、成员绑定、菜单、应用服务关联和 API 目录变更。一次批量语句最多更新每个受影响应用一次，回滚时标记和权限一起回滚。应用更新也刷新标记；共享 API 变更使所有关联应用失效。TRUNCATE 不属于支持的管理操作，不应用于运行中的权限表。

每次鉴权先读取启用应用的失效标记，再读取配置目录的全部启用服务、按键排序并计算摘要，一起作为内部缓存身份。服务集合摘要确保远程服务禁用/移除不会被本地缓存永久遮蔽。这一层的规模由全局服务资源数决定，不属于应用自身的角色、绑定或接口数据；目录来自配置指定来源，远程模式还会增加一次目录网络读取。因此请求总耗时包含“元数据与目录读取”这一固定项，不能把纯 CPU 匹配耗时当作完整接口延迟。

本地按应用保留最多 64 个编译索引，命中时无需 Redis 或权限表扫描。冷加载先读 Redis 当前记录缓存；失效、缺片、损坏或超时则用单条 PostgreSQL 查询读取当前规范化表，利用同一 MVCC 语句取得一致的角色、授权、成员、目录和菜单。这个查询结果只是运行时当前数据，不写 JSONB 快照表。

若元数据读取和当前数据读取之间有保存提交，查询拒绝旧标记，最多重新读取 3 次，持续并发变更则返回冲突而非使用过时缓存。同一应用/标记的并发编译通过 singleflight 合并。构建完成后索引只读，在途请求持有的旧指针不被原地修改。

缓存冷加载和 CPU 编译仍是 O(N)，其中 N 为接口、角色、用户角色边、角色接口边与路径数据总量；修改后首次鉴权可能重建整个应用索引。不会给角色的每个用户复制其所有 API。进一步按角色增量编译可作为后续优化，当前不声称单接口修改只产生 O(1) 重建成本。

## 管理界面与接口

角色编辑页提示“保存后角色授权立即生效”。用户分配保存、移除用户和删除角色直接影响鉴权。左侧保留“权限验证 → 权限模拟”，删除发布页面、发布菜单和发布 HTTP 路由；模拟按当前配置验证请求。API/菜单定义变更也直接生效，应复核共享服务的影响范围。

## 初始数据库结构

第一次安装使用 `migrations/000_create_database.sql` 创建数据库，再使用 `migrations/001_init.sql` 创建完整 schema。`001_init.sql` 已直接包含应用策略失效标记、语句级触发器和默认空域，不依赖其它初始化文件。

第一次安装必须连接空库执行完整脚本。脚本自带顶层事务，不插入业务种子数据，也不创建发布版本、历史快照或迁移记录表。初始化完成后由管理员通过 Dashboard 或管理 API 创建应用、服务、API、角色、菜单和用户绑定。

Redis 当前 key 规范、分片限制和故障行为单独见 [Redis 接入说明](redis-integration.md)；算法和大绑定量基准见 [鉴权匹配与性能](authorization-matching.md)。
