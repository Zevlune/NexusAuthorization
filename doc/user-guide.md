# 权限中心使用手册

## 适用范围

本手册面向在权限中心里配置业务应用权限的管理员，说明在 dashboard 上完成“选应用 → 关联服务 → 配接口与菜单 → 配角色 → 分配用户 → 模拟验证”的完整操作。

权限中心以业务应用组织权限配置：一个应用拥有自己的服务关联、菜单与按钮、角色和用户绑定，并从共享 API 目录选择接口授权。服务资源是跨应用共享的 API 目录，应用必须先关联某个服务，才能给它的接口配置授权。服务 API 运行时合并所有启用应用对该服务的有效授权；角色、绑定、菜单和 API 保存后直接参与对应鉴权路径，没有发布或版本步骤。

本手册只讲界面上的实际操作与含义。安装、数据库初始化、反向代理和环境变量配置见 [快速开始](quick-start.md)、[数据库初始化](../migrations/README.md) 和 [运维操作手册](operations-manual.md)。

## 登录

1. 打开权限中心地址，进入统一登录页。
2. 点击「统一登录」，浏览器跳转到统一登录服务（NexusAuth）完成身份验证。
3. 验证成功后自动回到权限中心，进入「选择业务应用」页。

本地体验若禁用 OIDC，会以开发身份直接进入，无需跳转统一登录。

右上角头像下拉可「账号设置」（在统一登录服务中管理账号）和「退出登录」。退出登录会结束当前会话并清空本地的页签记录；再次访问需重新登录。

## 前置准备

开始配置前，请确认：

- 已拿到可登录权限中心的账号，且服务端已完成统一登录（OIDC）配置。
- 后端已启动，数据库已完成首次初始化；相关步骤见 [快速开始](quick-start.md) 与 [数据库初始化](../migrations/README.md)。
- 需要纳管接口的服务已经以服务资源形式存在。服务资源可以来自本地目录，也可以来自统一认证服务的远程目录。
- 如果要给真实用户分配权限，统一认证服务的 SCIM 用户目录已配置；未配置时用户列表查询不可用，其余功能不受影响。

## 逐步操作

### 1. 选择或新建业务应用

登录后先进入「选择业务应用」页：

1. 需要新应用时点击「新建应用」，在右侧抽屉填写：
   - 「应用名称」：便于识别的名称，例如“业务管理平台”。
   - 「应用标识」：全局唯一的标识，例如 `business.portal`；创建后不可修改。
   - 「应用地址」：选填。填写后，启用状态下卡片会出现「打开应用」，可在新标签页直接打开业务系统；只接受 `http` 或 `https` 地址，且不能带账号密码。
   - 「应用描述」：选填。
   - 「启用应用」：默认开启。停用后该应用不可进入，但仍可编辑并重新启用。
2. 已有应用可点击卡片选择，或用搜索框按名称、标识过滤。
3. 停用应用以「已停用」标记展示，需在编辑抽屉中重新打开「启用应用」后才能进入。
4. 选中应用后点击「进入权限配置」。

顶部 Header 会显示当前业务应用，随时可用「切换应用」返回本页重新选择。当前选择是会话级状态：刷新页面保留，关闭标签页后需要重新选择。

### 2. 关联服务资源

进入左侧「资源管理 → 服务资源」：

1. 在列表中找到应用要使用的服务。
2. 在对应行点击「关联」；已关联的行显示「取消关联」。
3. 已关联且启用的服务行可点击「查看 API」，跳转到该服务的接口列表。

需要注意：

- 「关联」只表示该应用可以使用这个服务的接口目录，本身不授予任何访问权限。
- 若角色仍授权了该服务的 API，取消关联会被拒绝；先在各角色中移除该服务的 API 授权，再取消关联。
- 服务来源为统一认证服务远程目录时，列表为只读，不能新建、编辑或删除服务。
- 本地目录可「新建服务」，填写服务名称、服务标识（创建后不可改）、Audience、描述与启用状态；已关联的服务不能删除，需先取消所有应用关联并清理该服务下的 API 端点。

### 3. 维护 API 接口

进入左侧「资源管理 → API 接口」：

1. 应用尚未关联可用服务时，页面会提示并给出「前往关联服务」。
2. 「新增 API」可手动填写：接口标识、摘要、目标服务、HTTP 方法、模块、路径（必须以 `/` 开头）、启用状态。编辑时目标服务不可更改。
3. 「导入 Swagger」可选择已关联且启用的服务，填写 Swagger URL 批量导入；导入完成后显示总计、新增与跳过数量。

导入与保存只把接口写入共享的接口目录，不会自动授予应用或角色任何权限；授权仍需在角色里单独配置。

### 4. 配置菜单与按钮

进入左侧「资源管理 → 菜单与按钮」：

1. 点击「添加」新建顶级菜单，或使用行内操作继续扩展。菜单行可「添加按钮」「添加子菜单」或「删除」；按钮行只有「编辑」「删除」。
2. 抽屉里选择「资源类型」为菜单或按钮，填写名称与权限标识，并选择上级菜单 / 所属菜单；菜单还可填写路由与组件。
3. 使用筛选栏按名称或权限标识搜索，按类型过滤；表格按顶层节点分页（25/50/100），翻页不会拆散父子结构。

层级规则：

- 菜单可以挂到任意层级的菜单下，层数不限。
- 按钮是叶节点，必须挂在菜单下，不能再添加子级，也不能作为其它节点的上级。
- 编辑时不能把节点自己或它的后代设为上级；已有子项的菜单不能改成按钮；有子项时需先处理子项再删除。
- 菜单路由选填，如填写需以 `/` 开头。

### 5. 创建角色并授权

进入左侧「RBAC 授权 → 角色管理」，点击「新增角色」，进入角色编辑器：

1. 填写「角色名称」「角色编码」（编码创建后不可修改）、说明，并用「角色启用」控制启停。
2. 在「菜单与按钮」标签页配置页面与操作权限：
   - 在左侧权限树选择节点；切换「允许访问此菜单」控制菜单可见性。
   - 右侧「本节点直接按钮」用于勾选该菜单下的具体操作按钮，也可「选择本节点全部按钮」。
   - 勾选按钮会自动补齐其有效的上级菜单。
3. 在「API 接口」标签页配置接口权限：
   - 左侧选择服务，右侧按接口、模块、方法筛选。
   - 可逐条勾选、用「仅看已选」复核，或「全选当前结果」批量勾选；批量只影响当前筛选出的接口。
4. 底部「查看已选权限」可复核本次新增与移除，确认后点「保存角色」。

保存成功后角色授权立即生效，运行时鉴权和权限模拟都会读取最新配置。

### 6. 为用户分配角色

在「角色管理」列表中找到目标角色，点击「分配用户」：

1. 在用户下拉框中按姓名、用户名或邮箱搜索并勾选用户；已停用用户带有「已停用」标记，不能新增分配。
2. 取消勾选会移除该用户在此角色下的成员关系，同时保留它的其它角色。
3. 点击「保存分配」。

说明：

- 用户列表来自统一认证服务的用户目录，权限中心不存储用户资料。
- 分配保存写入默认空域（`domain` 为空串），界面不提供 Domain 选择；旧值 `global` 视作同一默认域，其它具名 Domain 的既有绑定不受影响。
- 若某个用户已从目录中删除，原绑定仍会显示为「原绑定用户」，可以取消分配。
- 部分用户保存失败时抽屉保持打开并提示失败数量，再次保存只重试未完成的变更。

## 生效与鉴权

没有发布按钮和版本列表。角色的 API、菜单、启停以及用户绑定的改动在保存成功后直接进入运行时判断；停用应用会立即阻止该应用的鉴权请求。保存、删除、批量语句和回滚的事务与缓存一致性规则见 [权限生效设计](permission-lifecycle.md)。

### 模拟验证

进入左侧「权限验证 → 权限模拟」：

1. 在「目标服务」选择已关联且启用的服务，再从该服务的 API 目录选择「Path」；目录按服务共享，只列出当前服务下的路径。
2. 在「HTTP 方法」选择该路径拥有的方法；同一路径的多个方法会去重列出。
3. 在「用户」从 SCIM 目录选择用户，选项显示可识别的姓名与账号；停用用户不能作为模拟主体。
4. 路径包含 `{id}` 等参数时，在 Path 下方为每个参数填写实际值；补齐参数后提交的是替换后的实际路径，不会把 `{id}` 字面量当作请求路径。
5. 点击「运行测试」，查看结果。

表单没有 Domain 输入，模拟按默认空域判断。任意输入变化都会清空上一次结果，切换应用会清空已选服务、Path、方法和结果。

模拟按当前已保存的配置判断；如果结果与预期不符，先确认目标角色、API 授权、用户绑定和菜单是否已经保存成功。

### 业务服务接入鉴权

业务服务在运行时通过 SDK 或 `/api/v1/authorize` 发起鉴权，请求需要带上应用标识、服务资源、subject、方法和路径；domain 可选，省略即使用默认空域。Redis 策略合并所有启用应用对该服务的有效授权，应用标识不进入业务策略；服务未启用、接口不存在或合并结果没有角色授权时拒绝。鉴权响应不再包含发布版本号；接入细节见 [SDK 接入说明](sdk-application-integration.md) 和 [接口参考](reference-api-rbac-v1.md)。

## 最小配置示例

以下以已有的一个启用用户为例；用户 ID 使用目录中实际返回的值。

1. 新建应用 `order-console`，关联本地服务 `order-api`。
2. 在 API 接口页为 `order-api` 新增 `GET /orders/{id}`，接口保持启用。
3. 新增角色 `order-reader`，在「API 接口」里勾选该接口并保存。
4. 在该角色行点「分配用户」，选择目标用户并保存。
5. 在「权限模拟」选择 `order-api`，从 API 目录选 `GET /orders/{id}`，用户选择该用户，参数 `id` 填 `123`；实际请求路径为 `/orders/123`，应返回 `allowed=true` 和 `reason=allowed`。
6. 换一个未授权用户重试，应返回拒绝；移除原用户角色后立即重试，原用户也应被拒绝。

模拟不会发送真实业务请求。实际业务服务还需要完成 SDK 或 `/api/v1/authorize` 接入；仅在界面配置菜单或隐藏按钮不能保护后端接口。

## 常见问题

**登录后没有进入控制台，而是停在选择应用页？**
这是正常流程。选择业务应用后点击「进入权限配置」即可进入控制台；也可用 Header 的「切换应用」更换。

**点「进入权限配置」没有反应？**
请确认已选中一个「已启用」的应用。停用应用不能进入，需要先在编辑抽屉中重新启用。

**API 接口页的「新增 API」「导入 Swagger」是灰的？**
说明当前应用还没有关联可用的服务。先到「服务资源」关联并启用服务。

**服务资源不能新建、编辑或删除？**
该服务来自统一认证服务的远程目录，为只读；只有本地目录可写。另外，删除前须先取消所有应用关联，并清理该服务的 API 端点。

**取消服务关联失败？**
先在使用该服务的角色中移除 API 授权，再取消关联；仅停用角色仍保留授权关系，不能代替移除。

**菜单删除或改成按钮失败？**
检查是否仍有子项，或用按钮作为了上级。按钮是叶节点，必须先处理子项或改回菜单。

**角色保存后，实际鉴权没有变化？**
确认保存请求已经成功返回。角色、菜单、API、用户绑定在保存成功后立即参与鉴权，不需要发布；若仍与预期不符，用「权限模拟」复核用户、服务、方法和路径。

**权限模拟结果和刚配置的不一致？**
模拟检查的是当前已保存配置。确认目标角色、授权和用户绑定已保存成功，并确认目标服务已关联且启用。

**「分配用户」里搜不到用户 / 加载失败？**
用户列表来自统一认证服务的 SCIM 目录。目录未配置时查询不可用，页面会显示加载失败和「重试」；此时不能保存分配。配置方式见 [NexusAuth SCIM 用户列表](nexusauth-scim-users.md)。

**看不到“用户授权”菜单？**
用户分配已合并到「角色管理」的「分配用户」操作中，旧的用户授权入口不再单独提供。
